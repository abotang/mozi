# 墨子蓝方七类任务复用说明

## 1. 交付内容

本套脚本把七类任务拆成独立入口，共用一个经过校验的执行引擎：

| 独立脚本 | 任务类型 | `missionType/classify` | 必需配置 |
| --- | --- | --- | --- |
| `01-飞机战斗巡逻.ps1` | 飞机战斗巡逻 | `Patrol/AAW` | 飞机 GUID、空中巡逻区、空战挂载 |
| `02-飞机对空打击.ps1` | 飞机对空打击 | `Strike/Air` | 主攻机、蓝方空中接触、可选护航机、空战挂载 |
| `03-飞机对海打击.ps1` | 飞机对海打击 | `Strike/SEA` | 主攻机、蓝方水面接触、反舰挂载 |
| `04-飞机对地打击.ps1` | 飞机对地打击 | `Strike/land` | 主攻机、蓝方地面接触、对地挂载 |
| `05-空中预警.ps1` | 空中预警 | `Support/空` | 预警机、预警区域 |
| `06-舰艇海上巡逻.ps1` | 舰艇海上巡逻 | `Patrol/SUR_SEA` | 舰艇、海上巡逻区、出航/区内航线 |
| `07-舰艇对海攻击.ps1` | 舰艇对海攻击 | `Strike/SEA` | 舰艇、蓝方水面接触 |
| `08-删除任务及对应区域.ps1` | 删除任务及其专属区域 | `DeleteMission/delArea` | 蓝方 GUID、蓝方名称、任务 GUID、可选区域 GUID |

共享文件：

- `Invoke-MoziBlueMissionPlan.ps1`：公共执行引擎。
- `墨子蓝方七类任务配置.json`：唯一需要修改的参数文件。
- `reports/`：每次执行后的任务详情回读报告。

## 2. 下次换飞机时改哪些参数

在配置文件的对应任务节点中修改：

```json
{
  "enabled": true,
  "name": "任务名称",
  "existingMissionGuid": "",
  "unitGuids": ["新飞机GUID"],
  "escortUnitGuids": ["新护航机GUID"],
  "targetContactGuids": ["蓝方当前接触GUID"],
  "targetKind": "Aircraft",
  "loadoutGuid": "新挂载GUID"
}
```

- 新建任务时把 `existingMissionGuid` 留空。
- 修改已有任务时填任务 GUID。
- `unitGuids` 是执行任务的己方单元。
- `escortUnitGuids` 只用于打击任务，护航单元会以 `[护航]` 回读。
- `targetContactGuids` 必须来自**蓝方当前 contacts**，不能填红方真实单元 GUID。
- `loadoutGuid` 可留空，表示不换挂；飞机任务建议明确填写。

## 3. 区域配置

巡逻和预警任务必须有区域。已有区域可直接复用：

```json
"area": {
  "existingAreaGuid": "已有区域GUID",
  "typeId": "405",
  "name": "区域名",
  "remark": "说明",
  "points": []
}
```

新建区域时留空 `existingAreaGuid` 并给至少 3 个点：

```json
"area": {
  "existingAreaGuid": "",
  "typeId": "413",
  "name": "舰艇海上巡逻区",
  "remark": "任务区域",
  "points": [
    {"lon": 136.9, "lat": 16.7},
    {"lon": 137.75, "lat": 16.7},
    {"lon": 137.75, "lat": 17.55},
    {"lon": 136.9, "lat": 17.55}
  ]
}
```

常用类型：空中巡逻 `405`、空中预警 `407`、海上巡逻 `413`。

## 4. 舰艇巡逻航线

舰艇巡逻任务可同时配置：

- `routes.outbound`：出航航线。
- `routes.onStation`：区内巡逻航线。

新航线的点默认油门可能是 `0`。共享引擎在创建航线后会自动调用 `updataPlanWayPoint`，把油门设为配置的 `throttle`（默认 `2`），并回读验证。

## 5. 运行方法

先只校验配置，不修改想定：

```powershell
& '.\01-飞机战斗巡逻.ps1' -ValidateOnly
```

执行单个任务：

```powershell
& '.\02-飞机对空打击.ps1'
& '.\03-飞机对海打击.ps1'
& '.\04-飞机对地打击.ps1'
& '.\05-空中预警.ps1'
& '.\06-舰艇海上巡逻.ps1'
& '.\07-舰艇对海攻击.ps1'
```

也可以直接调用共享引擎并指定任务：

```powershell
& '.\Invoke-MoziBlueMissionPlan.ps1' `
  -ConfigPath '.\墨子蓝方七类任务配置.json' `
  -Task airSeaStrike
```

任务键：

- `airCombatPatrol`
- `airAirStrike`
- `airSeaStrike`
- `airLandStrike`
- `airEarlyWarning`
- `shipSeaPatrol`
- `shipSeaStrike`

## 6. 脚本的强制校验

脚本不会把“接口返回成功”直接当成任务成功，还会强制检查：

- 巡逻任务：`patrolmissionData.PatrolArea` 至少 3 点。
- 打击任务：`strikeMissionData.targetList` 非空。
- 空中预警：`supportmissionData.area` 非空。
- 区域 GUID 自动规范为 `{GUID}`。
- 规则先写、单元后分配，避免规则更新清空分配。
- 航线点油门不允许停留在默认 `0`。
- 无目标的打击任务直接拒绝执行。

## 8. 想定重启后的操作

1. 重新读取蓝方、单元、接触、任务、区域 GUID。
2. 更新配置文件；旧 GUID 不可复用。
3. 运行对应脚本的 `-ValidateOnly`。
4. 确认推演已启动；两次读取 `GetScenarioTime.CurrentTime` 应前进。
5. 执行任务脚本。
6. 查看 `reports` 中的回读报告和墨子界面。

## 9. 删除任务及其对应区域

巡逻和预警任务通常有对应区域。删除任务时，把任务 GUID 和区域 GUID 一并传入：

```powershell
& '.\08-删除任务及对应区域.ps1' `
  -MissionGuid '任务GUID' `
  -AreaGuid '区域GUID' `
  -SideGuid '蓝方GUID' `
  -SideName '蓝方' `
  -ValidateOnly

& '.\08-删除任务及对应区域.ps1' `
  -MissionGuid '任务GUID' `
  -AreaGuid '区域GUID' `
  -SideGuid '蓝方GUID' `
  -SideName '蓝方'
```

脚本严格按“先删任务、回读确认，再删区域、回读确认”的顺序执行。对空、对海、对地等没有区域的打击任务不传 `AreaGuid`，脚本只删除任务。

区域可能被多个任务复用。脚本发现 `missionList` 可能还关联其他任务时默认停止；只有人工确认确实要删共享区域后，才可追加 `-AllowSharedAreaDeletion`。删除结果写入 `reports/delete-*.json`。
